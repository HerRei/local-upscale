# LocalSR — Model library design study

14 September 2026 · Design direction and implementation brief · Draft for review

Published study with figures: https://claude.ai/code/artifact/67ca0c51-b029-4db5-a46b-5829e3fade36
Companion mockups (design canvas): https://claude.ai/code/artifact/d6b6ea80-ef0a-4f68-aa7d-2390ca13da73

the real `model-catalog.json`.

## 1. The job

LocalSR wants to offer more, and better, models without turning the Enhance pane into a model-zoo
browser. The pane must keep its current promise — choose a task, click Quick or Best, press Start —
while a growing catalog becomes reachable, honest about licences and hardware, and manageable on
disk.

Three audiences use the same pane. Photographers and people with one image want a result and do
not know what an architecture is. Technical early adopters want the exact checkpoint, its
provenance, and control. Automation users drive the CLI and watch folders and need the same choices
without a window.

The central idea: **intent in, instrument out.** The user describes the image and the goal. The
app names the model it will run, says where it came from, what it costs to download, and whether
it fits the machine — before Start, in the pane.

## 2. Product audit

Baseline: `v0.0.12-alpha`, Tauri/Svelte host, `fix/v0.0.12-release-pipeline`.

| Evidence | Consequence for the design |
| --- | --- |
| The Enhance pane exposes three model decisions at once: a Checkpoint dropdown, a “Restore before upscale” dropdown, and a face-aware checkbox (`App.svelte` model sections). | Dropdowns are the surface that becomes overwhelming as the catalog grows. Replace them with one resolved *plan* card that names what will run, stage by stage. |
| Quick and Best are momentary commands (`applyPreset` writes settings; nothing shows afterwards which one is active). | Make Quality a persistent selection so later refinements (content, fixes) re-resolve the model and the pane always shows the current answer. |

| `support_tier: labs` carries two meanings — experimental (SeedVR2, de-flicker) and licence unclear (NomosWebPhoto, HFA2k). Best Quality currently points at a Labs model. | Split validation status from rights status and define which combinations a preset may use. |

| README: Quick = SPAN NomosUni, Best = RealPLKSR NomosWebPhoto; the release preflight downloads both into an empty cache and runs inference. | Keep the two-recipe promise and the preflight. Content and fixes are refinements with defaults, not new required steps. |
| Below 1280 px the Enhance pane floats; below 920 px panes become pages (ADR 0003). | The library must work as a sheet over the workspace and as a full page. |

| The project's culture is explicit honesty (release index, `KNOWN_LIMITATIONS.md`, licence evidence per checkpoint). | Honesty is the library's differentiator: every row shows licence status, Labs status and fit. Nothing is listed that has not passed the evidence gates. |

References for structure and behaviour, not templates.

## 4. Principles

1. **Intent before instrument.** The user says what the image is and what they want. The app picks.
2. **Two decisions on the main path.** Task and Quality. Content and fixes are refinements with sensible defaults (Photo, no fixes).
3. **The model is an answer, never a question.** Name, licence, fit, and download size appear in the pane before Start.
4. **Curated, verified, grouped by what it does.** Architecture is small print in the detail view.
5. **Honest at the point of decision.** Licence status, Labs, fit, size — as badges on the row and in the plan card, in the project's existing vocabulary.
6. **Stable results.** Presets pin exact checkpoints. Catalog updates offer; they never switch a pinned preset.
7. **Offline after the first download.** Quick is tiny and offered at first run. The library works offline with installed models.
8. **Parity.** UI, saved recipes and the CLI resolve models with the same function and the same pins.

## 5. The design

### 5.1 The Enhance pane

```
TASK        Upscale · Restore · Upscale Video              (one rename: Denoise → Restore, decision §10.2)
QUALITY     Quick · Best                                    (persistent selection; each shows the model it
                                                             resolves to and the estimated time on this machine)
YOUR IMAGE  Content: Photo | Illustration                   (segmented; grows to a menu at 4+ types)
            Fix first: Noise · JPEG artifacts · Blur · Faces (chips; each adds a stage)
MODEL       plan card: one row per stage → model · licence · fit · size · state     [Change…]
Advanced ⌄  output, hardware, model library, policy switches
SUMMARY     input · output · model chain · device
```

The mockups assume decision §10.1 (NomosWebPhoto confirmed as CC BY 4.0). Until then the same
screens show Best resolving to HAT-L ×4 and NomosWebPhoto with “License being confirmed”. Strings such as
“this Mac” are the macOS variant of a platform-aware token. Buttons whose model is not installed show the
download size instead of a time (“SPAN ×4 · 4.5 MB download”).

What changes versus today:

- **Quality is a state.** Both buttons stay visible; the chosen one is highlighted (Best in its gold, Quick in its blue). Changing content or fixes re-resolves the model and the plan card updates. When the user picks a specific model in the library, neither is highlighted and the card header reads “MODEL · chosen by you · Back to Best”.
- **The button subtitles are estimates, not slogans.** “SPAN ×4 · about 4 s here” / “RealPLKSR ×4 · about 25 s here”, from the existing estimator for the selected media and device. The trade-off becomes concrete per image and per machine.
- **Content** replaces the hidden purpose dimension. Photo is default. Illustration covers anime, line art and flat-colour artwork. Further types (screenshot/text, pixel art, AI-generated) can be added only when a verified model exists for them.
- **Fix first** replaces the “Restore before upscale” dropdown and the face checkbox. Each chip maps to a stage and a model slot (§5.3). Users describe problems, not models.
- **The plan card** replaces the checkpoint dropdown, description, licence line and per-model download buttons. One row per stage in run order: stage label · model name · licence · fit · size · state (On this Mac ✓ / Download / Needs your file / Heavy here). A footer sentence says why this plan, in one line. “Change…” opens the library filtered to this job; clicking a row opens it on that slot.
- **Downloads are consolidated into Start.** If any stage is missing, the Start button reads “Download 288 MB, then upscale”. Downloads run in order with per-row progress, are hash-checked, and the job starts by itself when they finish (ADR 0003's “without another click”, kept). Cancel returns the row to Download.
- **Restore task.** Content is hidden; “Fix” chips are the main choice (at least one; stages run at 1× in order deblock → denoise → deblur). Quick/Best still choose lighter or heavier models for each fix.
- **Video task.** Engine (Frame-by-frame / SeedVR2 · Labs) stays. Content applies to the frame model; fixes do not apply; Faces stays Labs.

### 5.2 Resolution rules

Inputs: task, quality, content, fixes, requested scale, device memory, installed set, policy flags
(`allow_labs_in_presets`, `show_non_commercial_models`).

1. **Candidates** — models whose `engine_id` the installed worker supports; whose purposes match the content (`photo`/`general` for Photo, `illustration`/`anime` for Illustration); whose stage matches the slot; whose `native_scale ≥` requested scale (upscale slot) or `= 1` (fix slots).
2. **Eligibility for presets** — validation `supported` (Labs only with the policy flag) **and** rights `verified` or `attribution` (`clarifying`, `unresolved` and `non-commercial` never enter a preset; the user can still choose them in the library, per job).
3. **Fit** — `vram_estimate_mb` against usable device memory: *Runs well* below two-thirds of it, *Heavy here* above (safe-memory mode), *Too heavy* above the total. On Apple Silicon the shared pool includes the OS, so 6 GB on an 8 GB machine is Heavy. Models that fit rank above models that don't within the same quality tier; a model that doesn't fit is still eligible but shown as “Heavy here” with safe-memory mode.
4. **Order** — Quick: `speed_tier` desc, `quality_tier` desc, installed first, `size_bytes` asc. Best: `quality_tier` desc, `speed_tier` desc, installed first. Deterministic tiebreak on `model_id`.
5. **Pins** — the first resolution for a (task, content, quality, slot) stores `model_id`, `sha256` and `catalog_revision`. Pins persist across catalog updates; a new better candidate produces an offer in the pane (“Catalog updated · a newer model qualifies for Best · Photo … Switch / Keep”). Saved recipes store pins too, so a recipe reproduces the same output in a year.
6. **Fallbacks** — no eligible candidate for a content type: resolve the best general model and show an inline notice with the one-click escape hatch to the Labs/clarifying model for this job. A pinned model removed from disk: keep the pin, show Download. A pinned model removed from the catalog: keep it usable while installed, mark “no longer listed”.

This is the existing `rank_models_for_preset` in `presets.py` with content, eligibility and pins added. It should become the single source of truth (worker or Rust) and the TypeScript copy should go.

### 5.3 Fixes → stages → slots

| Chip | Stage kind (exists) | Quick slot | Best slot | Notes |
| --- | --- | --- | --- | --- |
| JPEG artifacts | `deblock` | FBCNN Color | FBCNN Color | Blind quality-factor prediction; no strength slider (as today). |
| Noise | `restore` | RealPLKSR Denoise ×1 | NAFNet SIDD Width64 | 30 MB vs 464 MB — the plan card shows the cost. |
| Blur | `restore` | NAFNet GoPro Deblur | NAFNet GoPro Deblur | Motion blur only; say so in the role line. |
| Faces | `face_restore` + detector | HAT-L ×4 Face (user file) | HAT-L ×4 Face (user file) | YuNet detector downloads on first use (MIT). Fidelity slider stays in Advanced. |

Run order: deblock → denoise → deblur → upscale → faces. Restore task: the same chain without the upscale stage.

### 5.4 The Model library

**Placement.** A sheet (1080 × 700 at 1440 px) over the dimmed workspace, so the image and the job
stay in view. Below 920 px the same component renders as a full page with the rail collapsed into a
segmented row. Entry points: “Change…” and the plan-card rows; “Model library…” in Advanced; the
app menu; the first-run card.

**Header.** Title; a context chip when opened for a job (“Choosing for Upscale · Best · Photo”);
search; catalog date and model count; “Check for updates” (manual today); close.

**Rail.** *For this job* (only when opened from the pane; compatible models for the current slot,
sorted by fit). *Browse:* Upscale photos · Illustration · Faces · Fix noise, blur, JPEG · Video (Labs). *On this Mac:* Installed (with total size) · Your own files.

**Row.** Display name derived from the catalog name minus its role suffix, with `4x` written `×4`
(“RealPLKSR ×4 NomosWebPhoto”), so it still matches docs and OpenModelDB · role line in plain
words (“Best photo detail; trained on real-world JPEG damage”) · badges (Quick/Best pin, licence,
Labs, fit) · Quality and Speed as four dots each · size · state (Installed ✓ / Not downloaded).
Rows are a listbox: arrow keys move, Enter opens the detail, Space downloads or selects.

**Detail.** Name, role, badges · one before/after comparison crop with the app's own divider
(produced with the real model on the project's licensed sample; captioned as a sample, not a
guarantee) · facts grid (scale, download, memory while running, speed, architecture, training data)
· “On this Mac” fit line naming the device and memory · licence and provenance block (licence with
link, author, source, exact filename, integrity, commercial use, attribution) · actions: Download /
Use for this job / Make my Best · Photo; “Preview on a crop of your image” (phase 3: run the model on
the visible 256 px crop and show the comparison in the preview pane — the most honest way to choose).

**Installed.** Same rows with “Used by Best · Photo” lines, last used, size, Verified state, Remove.
Total size in the header; “Reveal folder” opens the models directory. Removing a pinned model warns that the preset will
need a download again. Re-verify recomputes the hash.

**Your own files.** Import (safetensors preferred; pickle files keep the existing explicit
acknowledgement). Imported files appear as rows with “Your file”, no tiers, and the architecture
Spandrel detected on first load.

**Empty and offline states.** Offline: downloads disabled with “Offline — 5 models on this Mac”;
everything installed still works. Search with no result: “Nothing verified matches. Import your own
file, or suggest a model” (link to the repository). A group with no verified entry shows why in one
sentence rather than hiding.

### 5.5 Trust vocabulary

Semantic colours are the app's existing ones (green `#91cca1`, amber `#e7bc72`, red `#ffacae`,
Labs blue `#b9d0ff`); the accent stays for selection only.

| Badge | Source field | Meaning to the user |
| --- | --- | --- |
| Quick / Best | pins | This preset uses it. |
| Labs | `support_tier` | Packaged and load-tested; behaviour still being verified. Excluded from presets unless allowed in Advanced. |
| Licence name | `license_name` | Links to `license_url`. Neutral. |
| Attribution required | `attribution_required` | LocalSR keeps the notice in third-party notices. Still preset-eligible. |
| Licence being confirmed | `rights_status = clarifying` | Author asked to confirm terms. Not preset-eligible. |
| Rights unresolved · your file | `automated_download_allowed = false` | LocalSR won't download it; you import a copy you're licensed to use. |
| Non-commercial | `commercial_use_allowed = false` | Hidden unless “show non-commercial models” is on; never in presets. |
| Runs well / Heavy here / Too heavy | `vram_estimate_mb` vs device | Fits · safe-memory mode and slower · refused with an alternative. |
| Installed ✓ · size | install state | On this Mac, hash-verified. |
| New | `added_in_revision` | Added since the catalog you last saw. |

### 5.6 First run and offline

No model is present after installation. The Quality section gets a card above it: “Models aren't
bundled. LocalSR downloads the models you pick once, checks them, and keeps them on this Mac. Your
images never leave the computer.” with *Get Quick · 4.5 MB* and *Quick + Best · 34 MB*. The card
disappears once any model is installed. Start still works without it (“Download 4.5 MB, then
upscale”). Network use is named where it happens, consistent with the privacy stance.

### 5.7 Catalog updates

Today the catalog ships inside releases; “Check for updates” points at the release notes. Phase 3
adds a remote manifest: a static JSON file fetched over HTTPS without identifiers, signed
(ed25519/minisign) with a key the app carries, with `schema_version` pinned to what the installed
app understands. Entries must carry `sha256` and `size_bytes`; the app lists only entries whose
`engine_id`/architecture the installed worker supports. A refresh never changes a pin; it produces
offers and “New” badges. The check is manual by default with an opt-in weekly check, described in
Advanced with the same plainness as the model downloads.

### 5.8 Compact widths, keyboard, accessibility

The pane adds one segmented control and one chip row; it still fits the 340 px pane at 100–125 %
interface scale without horizontal overflow. At < 920 px the library becomes a page with the rail as
a horizontal segmented row and the detail as a second step. The library is fully keyboard
operable (rail = tablist, list = listbox, detail actions = buttons); focus uses the app's accent
outline; badges carry text, never colour alone; the comparison divider keeps the existing slider
semantics.

### 5.9 CLI parity

```
localsr enhance --task upscale --quality best --content illustration --fix jpeg,noise --scale 4 in.jpg
localsr models list [--installed] [--for upscale/photo/best]
localsr models install <model_id> | remove <model_id> | verify
localsr models pin upscale/photo/best <model_id>
```

The watch folder uses the same flags; a recipe file carries the same pins as the UI.

## 6. What ships at start

**Policy (curation gates).** A model enters the catalog only with (1) an exact upstream file, pinned
size and SHA-256; (2) rights evidence for the *weights*, not just the code (recorded in
`docs/model-licenses.md` as today); (3) a load and inference test with the release's Spandrel; and
— new for the library — (4) a visual check on the project's real-photo sample set, producing the
detail crops the library shows. A model enters a *preset* only when it is Supported and its rights
are verified or attribution-only.

**Slots and occupants.**

| Slot | Today | Status | Recommendation |
| --- | --- | --- | --- |
| Upscale · Photo · Quick | SPAN ×4 NomosUni · 4.5 MB | Supported · CC BY 4.0 | Keep. It is exactly what a Quick should be. |
| Upscale · Photo · Best | RealPLKSR ×4 NomosWebPhoto · 30 MB | Labs · quality 4 · rights *clarifying* (“CC-BY-0.4”) | Ask the author to confirm CC BY 4.0 (almost certainly a typo). Confirmed → Supported, stays Best. Not confirmed → the policy makes HAT-L ×4 the Best automatically; its role line must say it is bicubic-trained and weaker on real JPEGs. |
| Upscale · Photo · 2× | Real-ESRGAN ×2 · 67 MB | Supported · BSD-3 | Keep; surfaces when the user asks for 2×. |
| Upscale · Illustration | RealPLKSR ×4 HFA2k · 30 MB | Labs · clarifying | Same author, same question. Until then the pane shows the honest fallback. |
| Fix · JPEG | FBCNN Color · 288 MB | Supported · Apache-2.0 | Keep. Large for a fix; a lighter deblocker is a later candidate. |
| Fix · Noise | RealPLKSR Denoise (Quick) · NAFNet SIDD (Best) | Supported | Keep. Candidate: SCUNet for blind noise (verify weight terms). |
| Fix · Blur | NAFNet GoPro Deblur · 272 MB | Supported · MIT | Keep. |
| Faces | HAT-S / HAT-L Face | Rights unresolved | Import only, as designed. |
| Video | SeedVR2 3B / FP8 | Labs · Apache-2.0 | Keep in Labs. |

**Candidates from the notes** (DRCT, DAT, SwinIR, RGT, GRL, SCUNet, SAFMN, MoSR/MoESR, AuraSR,
Real-ESRGAN ×4). Treat every row as unverified until it passes the gates: a permissive *code* licence
says nothing about the *weights*, and benchmark PSNR on bicubic test sets says little about real
photographs. Suggested verification order, by product value: (1) a real-degradation photo model with
a clean licence as insurance for the Best slot — the official Real-ESRGAN ×4 release asset is the
natural first candidate because the ×2 already passed the same route; (2) SCUNet for the Noise fix;
(3) DRCT-L official weights as a “highest fidelity on clean sources” option beside HAT-L, only if the
weight terms are explicit; (4) SwinIR as a mid-tier. None enters a preset before gate 4.

## 7. Options considered and not chosen

- **Library as a workspace page** (like the benchmark panel). More room for samples, but it leaves
  the job and hides the image; the sheet keeps context and becomes a page only where the window is
  too small.
- **Expanding the list inside the pane.** No new surface, but 340 px cannot carry samples, licences
  and fit, and the list scrolls forever — the dropdown problem in a new shape.
- **Merging Upscale and Restore into one flow with an output-size selector** (Same · 2× · 4×).
  Cleaner in theory; it would move the video path and the current task-specific model sets at once.
  Worth revisiting after the pane restructure has settled.
- **Automatic content detection.** Useful later (a cheap flat-colour/line heuristic); it must never
  override an explicit choice, and it needs a confidence display. Not in phase 1–2.
- **Mirroring OpenModelDB.** Maximal choice, minimal trust. Contradicts the licence policy and the
  privacy of a bundled catalog.
- **Navigation by architecture** (HAT / SPAN / RealPLKSR). Meaningful to experts only; it appears
  as a fact in the detail view and as a search term.

## 8. Data model changes

**Catalog (`schema_version` 2)** — new per-model fields: `role` (one line, user-facing), `stage`
(`upscale | deblock | restore | face_restore | video`), `content` (`photo | illustration | any`;
`purposes` stays for compatibility), `rights_status` (`verified | attribution | clarifying |
unresolved | non_commercial`, derived today from the existing licence fields), `samples`
(`[{before, after, caption}]` — small crops shipped as resources), `supersedes` /
`superseded_by`, `added_in_revision`, `training` (one line: data set and degradation model). `support_tier` keeps only its validation meaning.

**Settings** — `quality` (`quick | best | custom`), `content`, `fixes` (set), `preset_pins`
(`{"upscale/photo/best/upscale": {model_id, sha256, catalog_revision}}`),
`allow_labs_in_presets` (false), `show_non_commercial_models` (false), `catalog_last_seen_revision`.

**Recipes** — add `content`, `fixes`, and pins with `sha256` per stage; `stages[]` already exists.

**Host commands** — `list_models` (with computed fit per device), `remove_model`, `verify_model`,
`pin_preset`, `resolve_plan` (the single resolution function), phase 3: `check_catalog_update`,
`preview_on_crop`.

## 9. Rollout

**Phase 1 — the pane (v0.0.13).** Quality as state with estimates; Content and Fix chips; the plan
card; consolidated downloads in Start; first-run card; `resolve_plan` as the one resolver; pins.
No new models. Acceptance: the existing empty-cache Quick/Best preflight still passes; a saved recipe
from v0.0.12 opens unchanged; keyboard operation of the new controls; the pane fits at 125 %.

**Phase 2 — the library (v0.0.14).** Sheet and page variants; rail, rows, detail, Installed, Your
own files; sample crops produced by a script from the project's licensed sample set; badges; remove
and re-verify. Verification of the first candidates through the four gates. Acceptance: every listed
model has evidence in `docs/model-licenses.md` (today only the v0.0.11 additions do; SPAN, both RealPLKSR
photo models, HAT-S, HAT-L, RealPLKSR Denoise and both NAFNets need backfilling) and a sample pair; offline library works; removal of a
pinned model produces the warning and the Download state.

**Phase 3 — updates and try-on-crop.** Signed remote catalog with offers and “New”; “Preview on a
crop of your image”; CLI `models` subcommands; optional content auto-suggest.

## 11. Definition of done

A user with one photo clicks Upscale → Best → Start and never meets a model name unless they look at
the plan card. A user with an anime frame sets Illustration and gets an honest answer about what is
verified. A power user opens the library, sees why each model is there, what it costs, whether it
fits, and where it came from, and can make any verified model their Best. Results are reproducible
because presets and recipes pin checkpoints. Storage is visible and reversible. The CLI produces the
same plan as the pane.
